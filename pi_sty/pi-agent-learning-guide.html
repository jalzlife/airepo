01Pi Agent 基本概念

●什么是 Pi

Pi（@earendil-works/pi-coding-agent）是一个极简的终端编码代理（minimal terminal coding harness / agent）。它让大语言模型（LLM）获得在本地文件系统中读写文件、编辑代码、执行 Shell 命令的能力，从而像一个"结对编程工程师"一样完成真实开发任务。

与 Claude Code、Codex 等工具的核心差异在于：Pi 刻意保持核心最小化，不把子代理（sub-agents）、Plan 模式、MCP、权限弹窗等能力"内置"进内核，而是通过一套统一的扩展机制（TypeScript 扩展、Skills、提示模板、主题、Pi 包）让用户按自己的方式构建工作流，"让工具适应你，而不是你去适应工具"。

一句话定位 Pi = 一个可编程、可扩展、多模型、本地运行的开源终端编码代理；核心极简，能力靠扩展与生态生长。

●核心理念与设计哲学

  • 极简内核（Minimal Core）：默认只给模型 4 个工具 read、write、edit、bash；其余能力按需加载。
  • 激进可扩展（Aggressively Extensible）：几乎所有能力都可以通过扩展（Extension）、技能（Skill）、提示模板（Prompt Template）、主题（Theme）、包（Pi Package）实现，无需 fork 内核。
  • 不替你决定工作流：内置默认值强大，但刻意不含 MCP、子代理、Plan 模式、权限弹窗、内置待办清单、后台 Bash —— 这些都可以自行构建或安装第三方包。
  • 多形态运行：同一内核以四种模式运行 —— 交互式（interactive）、打印（print）、JSON 事件流、RPC，并可嵌入为 SDK。
  • 本地优先、透明可控：以本地用户权限运行，会话以 JSONL 明文存储，Token/成本/缓存全程可见。
哲学金句（来自官方 README） "Pi is aggressively extensible so it doesn't have to dictate your workflow. Features that other tools bake in can be built with extensions, skills, or installed from third-party pi packages."

npm install -g --ignore-scripts @earendil-works/pi-coding-agent

# 方式二：官方安装脚本
curl -fsSL https://pi.dev/install.sh | sh

# 认证：API Key 方式
export ANTHROPIC_API_KEY=sk-ant-...
pi

# 或订阅方式（Claude Pro/Max、ChatGPT Plus/Pro、GitHub Copilot 等）
pi
/login        # 选择供应商完成 OAuth

# 进入后直接对话；默认提供 read / write / edit / bash 四个工具
pi "列出 src/ 下所有 .ts 文件"          # 交互式带初始提示
pi -p "总结这个代码库"                   # 一次性打印模式
cat README.md | pi -p "总结这段文字"     # 读取管道 stdin

●关键运行时组件

ModelRuntime

模型与认证中枢

管理 30+ Provider 的模型目录，解析认证优先级（运行时覆盖 → auth.json → 环境变量 → 自定义回退），支持目录缓存与限流刷新。

AgentSession

会话生命周期

管理消息历史、模型状态、压缩、事件流；提供 prompt() / steer() / followUp() / subscribe() / navigateTree()。

SessionManager

会话树存储

JSONL 文件读写，id/parentId 树结构，分支、标签、版本迁移（v1→v3）。

ResourceLoader

资源发现

扫描全局/项目目录，发现扩展、技能、模板、主题、上下文文件（AGENTS.md/CLAUDE.md）。

ExtensionRuntime

扩展运行时

通过 jiti 直接加载 TypeScript 扩展，注册工具/命令/快捷键/事件处理器，支持异步工厂。

SettingsManager

配置管理

全局 ~/.pi/agent/settings.json 与项目 .pi/settings.json 合并，项目覆盖全局。

●Agent 执行循环（一次请求的流程）

1
组装上下文：系统提示 + 上下文文件（AGENTS.md）+ 技能描述（XML）+ 会话历史/压缩摘要 + 用户提示。
2
调用 LLM：通过 ModelRuntime 选中模型（含思考档位）发起请求，流式返回文本/思考/工具调用。
3
工具执行：模型发起 tool call（如 bash、edit），先经扩展事件（如权限门禁）拦截/放行，再执行并返回结果。
4
结果回填：工具结果追加到会话，进入下一轮推理；期间可接收 steering/follow-up 队列消息。
5
上下文检查：若 tokens 超过 contextWindow - reserveTokens，触发自动压缩（compaction）后继续。
6
持久化与事件：每个消息/工具调用实时写入 JSONL 会话文件，并通过事件总线广播（供 TUI、扩展、SDK 消费）。

●会话存储模型（JSONL 树）

会话保存在 ~/.pi/agent/sessions/--<路径>--/<时间戳>_<uuid>.jsonl，每行一个 JSON 条目，通过 id/parentId 构成树，支持原地分支（不需要新建文件）。

┌ header ─ user: "你好" ─ assistant: "当然！…"
│                                    ├─ user: "方案A…" ─ assistant: "方案A…" ─ user: "成功" ← 当前活动叶子
│                                    └─ user: "其实方案B…" ─ assistant: "方案B…"   ← 另一条分支
# 条目类型：user / assistant / toolResult / bash_execution / compaction /
#          branch_summary / model_change / thinking_level / label / custom 等
分支操作
/tree（原地切换分支）、/fork（从历史消息另开新会话）、/clone（复制当前分支到新会话）
迁移机制
旧版本会话（v1 线性、v2 树）自动迁移到 v3
导出/分享
/export 导出 HTML/JSONL，/share 上传私有 GitHub Gist

●四种运行模式 + SDK

模式命令用途
交互式pi（默认）日常开发对话，完整 TUI、快捷键、消息队列
打印模式pi -p "…"一次性问答，输出后退出；支持管道 stdin
JSON 模式pi --mode json输出结构化事件流（JSON Lines），供脚本/管道解析
RPC 模式pi --mode rpcstdin/stdout 上跑 JSONL 协议，供非 Node.js 进程集成
SDKcreateAgentSession()嵌入 Node.js 应用，构建自定义 UI/自动化流水线
 
import { createAgentSession, ModelRuntime, SessionManager } from "@earendil-works/pi-coding-agent";

const modelRuntime = await ModelRuntime.create();
const { session } = await createAgentSession({
  sessionManager: SessionManager.inMemory(),
  modelRuntime,
});

session.subscribe((e) => {
  if (e.type === "message_update" && e.assistantMessageEvent.type === "text_delta") {
    process.stdout.write(e.assistantMessageEvent.delta);
  }
});
await session.prompt("当前目录有哪些文件？");

03Pi Agent 技术特性

●极简核心 + 激进可扩展

内核

默认 4 工具 + 8 内置工具

默认 read/write/edit/bash；完整内置 read/bash/powershell/edit/write/grep/find/ls。可用 --tools 白名单、--exclude-tools 禁用、--no-tools 全关（如只读审计模式）。

扩展

TypeScript 扩展（无编译）

通过 jiti 直接加载 .ts，可：自定义工具、替换内置工具、子代理、Plan 模式、权限门禁、路径保护、自定义压缩、自定义 UI、MCP 集成、Git 自动提交…

// ~/.pi/agent/extensions/my-ext.ts —— 一个最小扩展
export default function (pi) {
  pi.on("tool_call", async (event, ctx) => {
    if (event.toolName === "bash" && event.input.command?.includes("rm -rf")) {
      const ok = await ctx.ui.confirm("危险操作", "允许执行 rm -rf？");
      if (!ok) return { block: true, reason: "用户拒绝" };
    }
  });
  pi.registerTool({ name: "greet", label: "Greet", description: "打招呼",
    parameters: Type.Object({ name: Type.String() }),
    execute: async (_id, p) => ({ content: [{ type: "text", text: `Hello ${p.name}` }], details: {} }) });
}

●多模型、多 Provider、本地模型

  • 订阅登录：Claude Pro/Max、ChatGPT Plus/Pro（Codex）、GitHub Copilot、xAI、OpenRouter、Radius。
  • API Key：Anthropic、OpenAI、Azure OpenAI、DeepSeek、NVIDIA NIM、Google Gemini/Vertex、Amazon Bedrock、Mistral、Groq、Cerebras、Cloudflare、xAI、OpenRouter、Hugging Face、Fireworks、Together、MiniMax、Kimi、小米 MiMo 等 30+ 供应商。
  • 本地模型：内置 llama.cpp 路由服务器，/llama 下载/加载/卸载模型，/model 切换。
  • 模型热切换与循环：/model 或 Ctrl+L 切换，Ctrl+P 在 scoped models 间循环；Ctrl+S 保存启动默认。
  • 思考档位：--thinking 与 /thinking 控制 off→max 七档，可配每档 token 预算。
  • 自定义 Provider：models.json 声明兼容 OpenAI/Anthropic/Google 协议的 API；扩展可注册自定义 API/OAuth。

●会话树、分支与恢复

树形分支

原地探索备选方案

所有历史保存在单个 JSONL 文件，/tree 跳转到任意历史点继续，/fork//clone 另存新会话。

自动保存

会话按项目组织

自动保存到 ~/.pi/agent/sessions/；pi -c 继续最近会话、pi -r 浏览选择、--no-session 临时模式。

标签

书签与时间戳

/tree 内 Shift+L 打标签、Shift+T 切换时间戳，便于标记关键节点。

●上下文压缩（Compaction）与分支总结

长会话超出上下文窗口时自动压缩，把旧消息总结为结构化摘要，保留最近内容继续工作：

触发条件
contextTokens > contextWindow - reserveTokens（默认预留 16384 tokens）
保留策略
保留最近 keepRecentTokens（默认 20000）tokens，其余总结
手动触发
/compact [自定义指令]
分支总结
/tree 切换分支时可总结被放弃的分支，把上下文带入新分支
扩展定制
session_before_compact / session_before_tree 事件可拦截或自定义总结

摘要采用统一结构化格式（目标/约束/进度/关键决策/下一步/已读已改文件清单），并累积追踪文件操作。

●消息队列（Steering / Follow-up）

Agent 运行中仍可提交消息，实现"边跑边指挥"：

  • Enter → 排队一条 steering 消息，在当前回合工具调用完成后立即送达；
  • Alt+Enter → 排队一条 follow-up 消息，等 Agent 全部工作结束后送达；
  • Escape 中止并恢复队列消息，Alt+Up 取回消息重新编辑。

●Skills / Prompt Templates / Themes / Pi Packages

Skills

遵循 Agent Skills 标准

SKILL.md（frontmatter + 指令）+ 脚本/参考文档，按需加载（渐进式披露）。可直接复用 Claude Code（~/.claude/skills）与 Codex（~/.codex/skills）的技能目录。通过 /skill:name 调用。

Prompt Templates

可复用 Markdown 提示

放在 ~/.pi/agent/prompts/ 或 .pi/prompts/，支持 {{变量}} 占位，/模板名 展开。

Themes

终端主题热重载

内置 dark/light，放在主题目录即自动发现，修改文件立即生效。

Pi Packages

npm/git 打包分享

pi install npm:@foo/bar 或 git:github.com/u/r@v1；package.json 的 pi 字段声明资源，形成第三方生态。

●项目信任与安全模型

重要安全边界 Pi 不内置沙箱，以启动它的本地用户权限运行；项目信任只是"输入加载防护"，不是安全沙箱。运行不信任代码/自动化任务应放到容器、VM 或微 VM（官方提供 Gondolin、Docker、OpenShell 方案）。
  • 项目信任：首次进入含 .pi/settings.json、.pi/extensions 等资源的目录时询问是否信任；决定写入 ~/.pi/agent/trust.json；非交互模式用 --approve/--no-approve 或 defaultProjectTrust 控制。
  • 无权限弹窗：刻意不内置确认弹窗，建议在容器中运行或通过扩展构建符合企业安全要求的确认流程。
  • 遥测可关：PI_OFFLINE=1、PI_TELEMETRY=0、PI_SKIP_VERSION_CHECK=1 均可关闭联网行为。

●可观测、可编程、可集成

成本可观测

Token/缓存/费用实时

页脚显示输入/输出 token、缓存读/写（R/W）、缓存命中率（CH）、成本、上下文占用，总量含工具与总结消耗。

事件流

全事件订阅

text_delta / thinking_delta / tool_execution / compaction / turn / agent 生命周期事件，可被 TUI、扩展、SDK 消费。

进程集成

SDK / RPC / JSON

同一内核暴露 SDK（同进程类型安全）与 RPC（跨语言进程隔离）两种集成路径，另有 JSON 事件流。

# 只读审计（仅允许读取类工具）
pi --tools read,grep,find,ls -p "审查这份代码"

# CI 无头运行
pi --mode rpc --no-session
# 环境变量注入给 bash 工具：PI_SESSION_ID / PI_MODEL / PI_PROVIDER / PI_REASONING_LEVEL

●设计哲学差异（售前沟通要点）

Pi

"可编程优先"

把子代理、Plan、MCP、权限弹窗等都视为"可被扩展实现的能力"而非"内置功能"，追求最小内核 + 最大自由度。适合希望深度定制、统一到自有平台/流水线的团队。

Claude Code

"开箱即用"

把子代理、Plan 模式、MCP、Hooks、权限系统等直接内置，上手即完整，配合 Anthropic 生态（Claude 模型 + 企业控制台）快速落地。

Codex

"安全沙箱 + 云端协同"

强调内置沙箱安全与云端/IDE 多端协同，与 OpenAI 模型深度绑定，适合重视隔离与云协作的团队。

●选型建议（面向售前方案）

客户场景推荐理由
需要多模型/多云/本地模型，避免供应商锁定Pi30+ Provider + llama.cpp 本地，模型中立，MIT 开源可控
需要深度定制 Agent、嵌入自有平台/CIPiSDK + RPC + JSON + 扩展，可编程性最强
已有 Anthropic/Claude 生态，追求开箱即用Claude Code功能完整、Hooks/权限/子代理成熟、企业支持完善
已有 OpenAI/ChatGPT 生态，重视沙箱隔离与云端协作Codex内置沙箱、云端/IDE 多端、与 OpenAI 深度集成
企业合规：需要内置权限审批/沙箱即得即用Claude Code / Codex两者内置权限与沙箱能力更"即插即用"；Pi 需额外扩展/容器方案
开源、可审计、可二次开发、无许可成本PiMIT 协议，代码透明，可自由修改与再分发
统一复用已有 Claude/Codex Skills 资产Pi / 均可Pi 可直接读取 ~/.claude/skills 与 ~/.codex/skills
售前一句话总结 Pi 是"乐高底座"—— 给你最小但极其可扩展的内核，把决策权留给你的团队与平台；Claude Code 与 Codex 是"精装整机"—— 功能完整、生态绑定、开箱即用。选择取决于客户是"要自由定制"还是"要快速落地"。

05学习路径与资源

●建议学习顺序

  1. 安装与首跑：npm 安装 → /login 认证 → 完成一次读写改 + bash 的简单任务。
  2. 掌握会话：体验 /tree、/fork、/clone、/compact、pi -c / -r。
  3. 理解扩展：阅读 docs/extensions.md，写一个最小扩展（注册工具/拦截 tool_call）。
  4. 上手 Skills / 包：复用 Claude Code 技能目录，尝试 pi install 第三方包。
  5. 深入架构：读 SDK、RPC、session-format、compaction 文档，理解 Agent 循环与事件流。
  6. 集成实践：用 SDK/RPC 把 Pi 嵌入自有应用或 CI 流水线。
